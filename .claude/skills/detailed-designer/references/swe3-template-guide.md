3. `WP_Templates/Engineering/README.md`의 작성 규칙(DOCX: 작성 안내 교체 / DRAWIO: 안내 도형을 실제 요소로 교체 후 베이스라인 시 PNG 병행 / 명명 규칙)도 함께 확인한다.

## 2. TPL-SWE3-001 (SW 상세설계서) 목차 구조 — 반드시 이 순서/제목을 유지

```
표지 / 문서 통제(변경이력·작성검토승인 상태) / 목차   ※ TPL-SWE2-001과 동일한 공통 서식

1. 목적 및 적용범위 (1.1 목적 / 1.2 적용범위 / 1.3 적용 경계)
2. 모듈 분해              — 아키텍처 요소를 구현 단위로 분해, 각 단위 ID/책임/소스 위치
3. 상세 호출관계          — 함수/클래스 간 호출 순서, 의존 방향, 주요 데이터 흐름
4. 공통 자료형            — 공통 데이터 구조, 열거형, 단위, 범위, 불변조건, 직렬화 규칙
5. 핵심 함수 계약         — 입력/출력/사전조건/사후조건/부작용/예외/시간 제약 (→ unit-design-quality.md 1절)
6. 핵심 알고리즘          — 처리 순서, 판단 조건, 경계값, 계산 근거 (의사코드/흐름도) (→ 2절)
7. 정책 의사결정표        — 입력 조건 조합, 우선순위, 기대 동작, 충돌 해결 규칙 (→ 3절)
8. 상태전이 상세          — 상태 저장 위치, 전이 함수, 이벤트, 가드, 타이머, 초기화 (→ 4절)
9. Web 및 API 상세        — 엔드포인트, 요청/응답 구조, 검증, 오류 코드, 세션, 보안 경계
10. 오류와 방어 동작      — 유효하지 않은 입력/예외/자원 실패의 검출/처리/기록/복구
11. 코딩 및 검증 규칙     — 코딩 표준, 정적분석, 단위검증, 커버리지, 리뷰 기준 (→ iso26262-unit-design-principles.md)
12. 단위와 요구사항 할당  — 구현 단위 ↔ 아키텍처 요소 ↔ SW 요구사항 ↔ 단위시험 연결
13. 구현 경계             — 생성 코드, 외부 라이브러리, 플랫폼 종속부, 구현하지 않는 범위
14. 추적성                — 아키텍처/상세설계/소스파일/함수/단위시험 양방향 연결
15. 참고자료              — 아키텍처 설계서, 코딩규칙, API 문서, 외부 라이브러리 자료
```

각 절 "작성 안내" 문구는 실제 내용으로 교체한다.

## 3. TPL-SWE3-002 (상세설계 UML 및 호출관계, drawio) 작성 규칙

- 도형 구성은 SWE.2용 drawio와 동일(`boundary`/`actor`/`element`/`edge`)하되, 작성 안내 내용이 다르다: ① 구현 단위와 책임, ② 함수 또는 클래스 호출, ③ 입력 출력 자료형, ④ 설계 및 시험 추적 ID.
- 호출관계(시퀀스/호출 그래프)를 표현할 때는 `element`를 함수/클래스 단위로 세분화하고, `edge` 라벨에 호출 조건(항상/조건부)을 표기한다.
- 안내용 더미 도형은 실제 값으로 교체하거나 필요한 만큼 복제한다.
- 베이스라인 시 PNG로 내보내 `ENG-SWE3-001` 문서의 3장/6장/8장에 삽입한다.
