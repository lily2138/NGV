# SW 시스템 테스트 케이스 생성

## 개요

SW 요구사항 명세서 기반으로 SW 시스템 테스트 케이스를 생성하기 위한 방법론 스킬입니다. 이 스킬은 "무엇을 근거로, 어떤 기법으로, 어떤 원칙으로" 테스트 케이스를 설계할지에 대한 방법론만 정의합니다. 요구사항 분석, 사용자와의 확인, 실제 산출물(xlsx) 작성은 이 스킬을 사용하는 에이전트(예: `sw-system-tester` 서브에이전트)가 수행합니다.

## 기반지식

- **ISO 26262 Part 6**: 소프트웨어 단위/통합/시스템 테스트에 대한 요건. 특히 ASIL 등급이 할당된 요구사항은 판정기준의 전 분기(경계값, 조건 조합)를 빠짐없이 검증해야 합니다.
- **A-SPICE SWE.4, SWE.5, SWE.6**: 소프트웨어 단위 검증, 통합 시험, 시스템 시험에 대한 Base Practice. 양방향 추적성(요구사항 ↔ 테스트 케이스)과 표준화된 시험 절차를 요구합니다. 이 스킬이 다루는 범위는 그중 **SWE.6 성격**(SW 요구사항 명세서를 베이시스로 한 블랙박스 기능/비기능 검증)입니다 — 단위 검증은 `tdd` 스킬(SWE.3/SWE.4 관점), 아키텍처 인터페이스·통합순서 기반의 컴포넌트 통합 검증(코드 커버리지 포함)은 `integration-tester` 스킬(SWE.5)의 범위이며 이 스킬과 중복되지 않습니다.
- **ISO 29119 및 ISTQB**: 테스트 시나리오·테스트 케이스 설계 프로세스와 용어 체계(긍정/부정 분류 등)의 근거로 사용합니다.
- **ISO/IEC 25000 (SQuaRE) 품질특성**: 비기능(품질) 요구사항을 분류하는 기준입니다. 품질특성의 정확한 명칭·하위특성 목록은 `requirements-analyst` 스킬의 `references/iso25010-nfr-verification.md`(ISO/IEC 25010:2023, 9대 특성)를 그대로 따릅니다 — 이 스킬에서 별도로 다시 정의하지 않습니다. 요구사항 명세서에 이미 품질특성이 태깅되어 있으면 그것을 그대로 사용하고, 없으면 위 참고자료 기준으로 분류합니다.

## 적용 대상 테스트 기법

기법의 정의는 `../_shared/references/test-design-techniques.md`(전 단계 공용 taxonomy — `tdd`/`integration-tester`와 동일한 정의)를 따릅니다. 요구사항의 성격에 맞춰 그 문서의 기법 중에서 선택하여 적용하고, 각 테스트 케이스의 "사용 기법" 항목에 실제로 적용한 기법명(공용 문서의 명칭)을 그대로 명시합니다. 조합 수가 많아 페어와이즈를 적용할 때는 공용 문서의 PICT 사용법을 따릅니다.

## 작성 원칙

- 의미 없이 테스트 커버리지 수치 달성만을 목적으로 하는 케이스는 생성하지 않습니다.
- 테스트의 예상 결과를 임의로 가정하지 않습니다. 명세서에 근거가 없다면 이 스킬을 사용하는 에이전트가 사용자에게 확인을 받아야 합니다.
- 이 스킬이 책임지는 커버리지는 **요구사항 커버리지**(SW 요구사항 명세서의 모든 기능/비기능 요구사항이 최소 1개 이상의 테스트 케이스로 커버되는 것)입니다. 코드 수준의 함수/콜 커버리지는 `integration-tester` 스킬의 책임이며 이 스킬에서 측정하지 않습니다.
- 실행자가 그대로 재현할 수 있는, 실행 가능한 테스트 케이스만 작성합니다.
- 기법 선택이나 커버리지 범위 설정이 판단하기 어려운 경우 임의로 결정하지 말고, 이 스킬을 사용하는 에이전트를 통해 사용자 검토를 받습니다.
- 명세서에 직접적 근거는 없으나 QA 관점에서 추가를 제안하고 싶은 테스트 케이스는 테스트 케이스명 끝에 "(제안)"이라고 표시해 구분합니다.
- 사용한 테스트 설계 기법을 각 케이스에 명시합니다.
- CLAUDE.md 시스템 테스트 지침에 따라 이 단계는 요구사항 커버리지 100%와 테스트 성공률 100%를 모두 만족해야 완료로 봅니다. 테스트 케이스를 실행해 실패가 발생하면(이 스킬을 사용하는 에이전트가 실행하는 경우), 결함인지 예상 결과 정의 오류인지 규명하기 전까지 해당 단계를 완료로 보고하지 않습니다.

## 도구 사용

- 페어와이즈/전수 조합 생성 도구(PICT)의 설치·명령어·옵션은 `../_shared/references/test-design-techniques.md`의 "PICT" 절을 따릅니다 — 여기서 별도로 정의하지 않습니다.

## 산출물 구조

- 기능 요구사항에 대한 테스트 케이스: "테스트 케이스" 시트
- 비기능 요구사항에 대한 테스트 케이스: 별도의 "비기능 테스트 케이스" 시트, ISO/IEC 25010:2023 품질특성별로 구분 (`requirements-analyst`의 `iso25010-nfr-verification.md` 기준)
- 요구사항 원문에 없거나 원문보다 엄격하게 사용자 확인을 거쳐 확정한 판정기준: "확정 근거" 열에 확정 일자와 승인 주체 기록
- **추적성**: 생성한 테스트 케이스 ID를 `requirements-analyst`가 관리하는 추적성 매트릭스(RTM, `ENG-TRC-001`)의 `SWE.6` 컬럼에 같은 작업 안에서 반영합니다 (RTM 컬럼 정의는 `requirements-analyst`의 `uml-sysml-traceability.md` 4절을 따릅니다).
