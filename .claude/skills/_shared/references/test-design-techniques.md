# 테스트 설계 기법 공통 taxonomy (전 단계 공용)

> 이 파일은 `tdd`(SWE.3/단위), `integration-tester`(SWE.5/통합), `sw-system-test`(SWE.6/시스템) 세 스킬이 공유하는 단일 기법 정의다. 각 스킬은 이 문서를 참조하고, 기법의 정의를 자체적으로 다시 정의하지 않는다 — 적용 대상(무엇에 적용하는가)만 각 스킬에서 설명한다. 새 테스트 관련 스킬을 추가할 때도 이 목록에 없는 기법을 임의로 새로 정의하지 말고, 필요하면 이 파일에 추가하고 모든 사용처에서 공유한다.

| 기법 | 정의 | 적용 예시 (단계별) |
|---|---|---|
| **동등분할** (Equivalence Partitioning) | 입력/조건의 정의역을 유효/무효 클래스로 나누고 각 클래스의 대표값으로 케이스를 도출한다 | 단위: 함수 인자의 정상/비정상 값 클래스. 통합: 인터페이스 입력 클래스. 시스템: 요구사항 입력 조건 클래스 |
| **경계값분석** (Boundary Value Analysis) | 유효/무효 클래스의 경계(최소, 최대, 경계 바로 안/밖)를 각각 별도 케이스로 도출한다 | 단위: 함수 계약의 사전조건 경계. 통합: 인터페이스 값 범위 경계. 시스템: 요구사항 판정기준의 수치·임계값 경계 |
| **의사결정표 / 전 조건 조합 테스트** (Decision Table / Full Combination Testing) | 여러 조건의 조합에 따라 달라지는 동작을 표로 정리하고, 조건 수가 적어 전수 조합이 실행 가능하면 모든 조합을 케이스로 도출한다 | 단위: 상세설계의 정책 의사결정표(7장). 통합: 인터페이스 조건 조합. 시스템: 요구사항의 조건 조합(전수 가능 범위) |
| **페어와이즈 조합 테스트** (Pairwise Testing) | 조건·값의 조합 수가 많아 전수 조합이 비현실적일 때, 모든 두 조건 쌍(pair)을 최소 1회 커버하는 대표 조합만 선택한다 | 통합: 다중 인터페이스 파라미터 조합. 시스템: 다중 설정/옵션 조합 |
| **상태전이 테스트** (State Transition Testing) | 상태·이벤트·가드·전이를 모델링하고, 허용 전이와 금지 전이를 각각 케이스로 도출한다 | 단위: 상세설계 상태전이 상세(8장). 통합: 컴포넌트 간 상태 동기화. 시스템: 요구사항에 정의된 모드/상태 전이 |
| **엣지 케이스** (Edge Case) | 정상 범위의 극단, 동시성·타이밍 등 위 기법들로 포착되지 않는 특이 조건을 다룬다 | 통합: 타이밍 의존적 인터페이스 상호작용. 시스템: 동시 요청, 자원 소진 직전 상태 등 |
| **오류추측 / 경험기반 테스트** (Error Guessing / Experience-based Testing) | 유사 시스템의 결함 이력이나 테스터의 경험에 근거해 결함이 있을 법한 조건을 추정한다 | 전 단계 공통 — 명시적 근거(계약/인터페이스/요구사항)로 도출되지 않는 나머지 위험 영역을 보완 |

## 페어와이즈 조합 생성 도구 — PICT (오픈소스)

조합 수가 많아 페어와이즈 기법을 적용할 때는 오픈소스 도구 [PICT](https://github.com/microsoft/pict)를 사용한다.

```bash
# 입력 모델 파일(model.txt)에 파라미터와 값을 정의한 뒤 페어와이즈 조합 생성
pict model.txt > pairwiseCases.txt

# 전수 조합(모든 조건의 조합)이 필요하면 /o(order) 옵션을 조건 수만큼 지정한다
pict model.txt /o:3 > fullCombinationCases.txt
```
- 페어와이즈(기본): 옵션 없이 실행하면 2-way(모든 쌍) 조합을 생성한다.
- 전 조건 조합이 필요하면 `/o:<조건 수>`로 order를 조건 개수와 같게 지정해 전수 조합을 생성한다 (조건 수가 적어 실행 가능한 범위일 때만 사용 — 의사결정표 기법과 동일한 목적).
- 모델 파일 작성법과 옵션 전체 목록은 PICT 공식 문서를 따른다.

## 이 문서를 사용하는 스킬

- `tdd`: `references/swe3-test-case-derivation.md`에서 SWE.3 함수 계약 요소(사전조건/경계값/의사결정표/상태전이)별로 위 기법 중 무엇을 적용할지 매핑한다.
- `integration-tester`: `references/iso26262-integration-test-principles.md`에서 SWE.2 아키텍처 인터페이스/상호작용에 위 기법을 적용하는 방법을 설명한다.
- `sw-system-test`: SWE.1 SW 요구사항 명세서의 판정기준에 위 기법을 적용하는 방법을 설명한다.

기법 이름이나 정의를 바꿔야 할 필요가 있으면, 이 파일 하나만 수정하고 세 스킬 모두에 자동으로 반영되도록 각 스킬은 이 파일을 참조만 하고 복제하지 않는다.
