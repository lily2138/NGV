# A-SPICE 4.1 CL2 산출물 감사 스킬

이 스킬은 Claude를 A-SPICE CL2 갭 분석 보조 도구로 만듭니다. 이 스킬은 **공인 intacs 심사원을 대체하지 않습니다** — 모든 결과물은 사전 점검용 자가 갭 분석으로 표현해야 하며, 공식 역량 등급으로 표현해서는 안 됩니다.

## 참고자료 (필요할 때 불러오고, 통째로 대화창에 붙여넣지 말 것)

- `references/gp-2.1-2.2-checklist.md` — GP 2.1.1~2.1.6(PA 2.1)과 GP 2.2.1~2.2.4(PA 2.2)의 공식 원문(영문), 프로세스 속성 성과 목록, 전형적인 출력 작업제품, 그리고 바로 활용 가능한 증적/갭 매핑표. **매번 가장 먼저 읽어야 하는 파일**이며, 등급 판정의 핵심 기준입니다.
- `references/process-scope.md` — 프로세스 그룹별(ACQ/SPL/SYS/SWE/VAL/MLE/HWE/SUP/MAN/PIM/REU) A-SPICE 4.1 전체 프로세스 목록과, 일반적인 VDA 공급사 심사 범위 서브셋.
- `references/information-item-characteristics.md` — 공식 Annex B(정보항목 특성) 발췌본. 정보항목 ID/명칭(예: `13-19 Review evidence`, `08-56 Schedule`, `18-52 Software requirements specification`)별로 무엇을 식별하고 포함해야 하는지 정리되어 있습니다. 실제 문서가 적절한지 판단하기 전에 이 파일을 검색해서 해당 산출물 유형이 통상 어떤 형태여야 하는지 확인하세요. 표준 원문에 명시된 대로, 이 특성 목록은 **합격/불합격 체크리스트가 아니라** 잘 작성된 산출물이 통상 포함하는 내용에 대한 참고 가이드입니다.

> 위 참고자료는 VDA QMC가 공개한 Automotive SPICE PAM 4.1(프리뷰) 공식 원문에서 발췌한 것으로, 표준 원문의 정확성을 위해 영문으로 유지합니다. 점검 절차, 보고서 형식 등 이 SKILL.md 자체의 지침은 한국어로 작성되어 있습니다.

## 감사 절차

1. **범위 확정.** 어떤 프로세스를 점검할지(예: "SWE.1, SWE.2, SUP.8" 또는 "SYS/SWE 전 프로세스") 확인하세요. 사용자가 "통상 범위"라고만 말하면 `references/process-scope.md`에서 전체 프로세스 목록과 일반적인 VDA 심사 범위를 참고하세요.
2. **증적 위치 파악.** Read/Grep/Glob으로 사용자가 안내한 저장소/파일 시스템에서 실제 산출물(요구사항 문서, 아키텍처 문서, 테스트 명세/결과, 리뷰기록, 형상관리 기록, 프로젝트 계획서, 변경요청/문제보고서 등)을 찾으세요. 아무것도 찾지 못하면 존재를 가정하지 말고 사용자에게 위치를 물어보세요.
3. **CL1 선확인.** CL2는 기본관행(프로세스 성과, outcome)이 이미 수행되고 있어야 의미가 있습니다. 어떤 프로세스의 핵심 산출물이 아예 존재하지 않는다면, PA 2.1/2.2를 평가하기 전에 먼저 PA 1.1(CL1) 갭으로 지적하세요.
4. **프로세스별로 PA 2.2(작업제품관리)를 산출물 단위로 평가**하세요. 체크리스트 참고자료의 GP 2.2.1~2.2.4를 사용합니다.
   - 2.2.1: 이 산출물 유형에 대한 템플릿/표준/품질기준/리뷰기준이 정의되어 있는가?
   - 2.2.2: 저장/통제/명명규칙/상태모델 요구사항이 정의되어 있는가?
   - 2.2.3: 실제 산출물이 식별되고, 형상통제 하에 저장·버전관리되며, 필요한 경우 베이스라인이 설정되어 있는가?
   - 2.2.4: 리뷰기록이 있고 지적사항이 해결(종결)까지 추적되는가?
5. **프로세스/프로젝트 단위로 PA 2.1(프로세스 성과관리)을 평가**하세요. GP 2.1.1~2.1.6을 사용합니다. 프로세스 성과 목표(단순 프로젝트 목표와는 구분됨 — 체크리스트 참고자료의 예시 참고), 계획/일정, 자원 필요량/할당, 모니터링/진척현황, 역할 간 인터페이스/커뮤니케이션 기록을 확인하세요.
6. **각 GP를 표준 등급 척도로 평가**하세요 — N(0~15%), P(15% 초과~50%), L(50% 초과~85%), F(85% 초과~100%) — 실제 근거(파일 경로, 문서명, 또는 "찾지 못함")를 한 줄로 인용하며 판정하세요. CL2 달성에는 PA 1.1 = F, PA 2.1과 PA 2.2가 모두 L 이상이어야 합니다.
7. **프로세스별로 결과를 보고**하세요. GP별 등급, 인용된 증적, 구체적인 갭 설명, 갭 해소를 위한 실행 가능한 권고사항을 포함해야 합니다. 증적을 지어내지 마세요 — 산출물을 찾지 못했다면 그렇다고 명시하고 그에 맞게(대개 N 또는 P) 등급을 매기세요.

## 출력 형식

다음과 같은 구조화된 마크다운 보고서를 우선 사용하세요.

```
## <프로세스 ID> <프로세스명>
PA 1.1 (프로세스 성과/outcome): <상태/비고>
PA 2.1 프로세스 성과관리: <N/P/L/F>
  GP 2.1.1 ... : <등급> — <증적 또는 갭>
  ...
PA 2.2 작업제품관리: <N/P/L/F>
  GP 2.2.1 ... : <등급> — <증적 또는 갭>
  ...
주요 갭:
  - ...
권고사항:
  - ...
```

여러 프로세스를 점검하는 경우, 최상단에 프로세스 × PA 2.1/PA 2.2 등급을 요약한 표를 추가하세요.
